---
title: "Shell"
description: "A terminal in the session's workspace, on the computer."
---

```bash
opc shell 7f3a
```

`opc shell` opens an interactive shell on the computer, in the session's workspace, as the same user the agent runs as. It behaves like `ssh`: your terminal talks straight to the remote shell, with colors, full-screen programs and resizing. `exit` or `Ctrl+D` closes it.

Inside a session, `/shell` does the same and returns to the session screen when the shell exits.

- **Which session.** The id, or the session you last attached to on this machine when omitted. A suspended session stays suspended: the shell does not need the agent, so it opens at once.
- **What you see.** The same files the agent sees, live. Changes you make are visible to the agent at once, and the other way round.
- **While the agent works.** Allowed. You and the agent share one filesystem, so avoid editing a file the agent is editing.
- **How long it lasts.** Until you exit or disconnect. A dropped connection ends the shell and its foreground program, as with `ssh`. Use `tmux` on the computer for anything that must survive.
- **Suspending.** A session with an open shell is not suspended for being idle.
- **Secrets.** The session's secrets are not in the shell's environment. The shell is for looking around, not for acting as the agent.

| Option | Does |
| --- | --- |
| `-c`, `--command <command>` | Runs one command instead of an interactive shell, prints its output and exits with its exit code |
| `--no-tty` | No terminal on the remote side, for piping binary output |

```bash
opc shell 7f3a -c 'git -C billing log --oneline -5'
opc shell 7f3a -c 'tar -C reports -c q3' --no-tty | tar -x
```
