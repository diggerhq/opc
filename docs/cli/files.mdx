---
title: "Files"
description: "opc push and opc pull: the only ways files move between your machine and the computer."
---

The computer has what you pushed. You have what you pulled. Nothing moves on its own: `opc` never reads a local file unless you name it in `opc push`, and never writes one unless you run `opc pull`.

For code in a repository, this is often unnecessary. The workspace already has every repository your organization connected, and the agent's work comes back as a branch and a pull request. Push and pull are for what is not in a connected repository: a local checkout with uncommitted changes, a scratch directory, a data file, a generated report.

## Push

```bash
opc push                     # the current directory, into the last session on this machine
opc push ~/src/billing -s 7f3a
opc push . --to billing-wip  # under a different name
```

```
$ opc push ~/src/billing
pushing to 7f3a "flaky test in segment.test.ts" (attached 3d ago)
↑ billing → workspace/billing · 412 files · 3.1 MB · 0.9 s
```

`opc push <dir>` copies the directory to `workspace/<name>`, where `<name>` is the directory's name, or the one given with `--to`. The agent can use it from its next step. Its next turn begins with a note that you pushed it, so you do not need to tell it.

**What is sent.** Every file under the directory, including hidden ones such as `.github`, except:

- `.git`, always. The workspace copy is plain files, not a repository.
- Files matched by `.gitignore` files in the directory and its subdirectories, and by `.opcignore` with the same syntax. This keeps `.env`, `node_modules` and build output at home. `--no-ignore` sends them anyway; `.git` is still excluded.

Symbolic links are sent as links. File modes are kept for the executable bit only. Files are owned by the agent on the computer.

**Where it goes.** `--to` takes a name, not a path: one level under the workspace. A name already used by one of your organization's repositories, or by anything the agent created, is refused:

```
opc: workspace/billing-service already exists and was not pushed by opc. Use --to <another name>.
```

Pushing again to a name you pushed before replaces it entirely, and says so: `replaced workspace/billing (previously pushed 14m ago)`. Files the agent changed there are lost, so pull them first if you need them.

**Which session.** `-s <id>` names it. Without it, `opc push` uses the last session on this machine, the one most recently created or attached here, and prints which one before sending, so a push never lands somewhere unexpected. It does this only when standard input is a terminal: from a script, `opc push` without `-s` fails with `pass -s <id>`. `opc -p --push <dir>` and `opc new --push <dir>` push into the session they create, before the message is sent.

**How fast.** Files travel as one compressed stream, at 50 MB/s or more when you are in the same region as your computer.

| Option | Does |
| --- | --- |
| `-s`, `--session <id>` | Target session |
| `--to <name>` | Name under the workspace |
| `--no-ignore` | Ignore `.gitignore` and `.opcignore` |
| `--dry-run` | Lists what would be sent, and its size, and sends nothing |
| `--idempotency-key <key>` | Makes a repeat of the same push, such as a retry in CI, harmless. Keys last 24 hours. |
| `--json` | Prints `{ sessionId, path, files, bytes, replaced }` |

**Limits.** 1 GiB and 100,000 files per push, measured after ignores. `--dry-run` tells you where you stand.

## Pull

```bash
opc pull billing                 # workspace/billing → ./billing
opc pull reports/q3 ~/Desktop/q3
opc pull billing . --force       # into the current directory, overwriting
```

```
↓ workspace/reports/q3 → ./q3 · 12 files · 280 KB · 0.3 s
```

`opc pull <path> [dir] [--force]` copies a directory or file from the workspace to your machine. `<path>` is relative to the workspace, and may be any directory in it, including a repository. `[dir]` defaults to `./<last part of path>`.

**What is received.** Everything under the path except `.git`. Ignore files are not applied: you asked for these files, build output included.

**Where it goes.** A destination that does not exist is created. An existing empty directory is filled. An existing directory with files in it is refused unless you pass `--force`, which overwrites files with the same name and leaves every other local file alone. `opc pull` never deletes a local file.

| Option | Does |
| --- | --- |
| `-s`, `--session <id>` | Source session. Default, when standard input is a terminal: the last session on this machine. |
| `--force` | Writes into a directory that already has files |
| `--dry-run` | Lists what would be written, and what it would overwrite |
| `--json` | Prints `{ sessionId, path, files, bytes, overwritten }` |

**Limits.** 1 GiB and 100,000 files per pull.

## Inside a session

`/push` and `/pull` do the same in the [session screen](/terminal/slash-commands#push), for the session you are in.

## Not supported

Live sync, mounting your machine into the computer, and running the agent's tools on your laptop.
