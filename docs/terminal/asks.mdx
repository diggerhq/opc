---
title: "Asks"
description: "Approvals, questions and secrets: when the agent needs a person."
---

When the agent needs a person, it raises an ask. `opc` draws it inline and gives it the keyboard. The session's status is `waiting` until the ask is answered, from here or from any other client.

## Approvals

The agent wants to do something your permission mode does not allow on its own.

```
  ? Bash  terraform apply -auto-approve
    in infra/staging · wants approval
    [y] allow   [n] deny   [a] allow for this session   [e] deny and say why
```

| Key | Does |
| --- | --- |
| `y` | Allows this call |
| `n` | Denies it. The agent is told it was denied and carries on. |
| `a` | Allows this call and every later call of the same tool with a matching input, for the rest of the session. For `Bash`, matching means the same command name, such as every `terraform` command. |
| `e` | Denies it and opens a line for a reason, which the agent reads |
| `Ctrl+O` | Shows the full input, such as the whole command or diff |

An approval in `plan` mode is the plan itself: the full plan is shown, and allowing it switches the session to `default` mode so the agent can start.

## Questions

The agent asks one or more questions, each with choices.

```
  ? Which fix do you want?
    ❯ Make the test wait for the debounce   (recommended)
      Make flush() await pending timers
      Something else…
    ↑↓ move · enter choose · tab to the prompt line
```

| Key | Does |
| --- | --- |
| `↑` `↓` | Move between choices |
| `Enter` | Chooses, or moves to the next question when there are several |
| `Space` | Toggles a choice, when the question allows several |
| `1`–`9` | Chooses by number |
| Typing on **Something else…** | Answers in your own words |
| `Ctrl+X` | Dismisses the question. The agent is told nobody answered and decides how to go on. |

When there are several questions, the answers are sent together after the last one.

## Secrets

The agent needs a credential, such as an API key, that the session does not have.

```
  ? Secret STRIPE_API_KEY needed
    "To run the billing integration tests against Stripe's test mode."
    [enter] type it here (hidden)   [w] set it on the dashboard   [x] skip
```

A secret never goes into the conversation. When you press `Enter`, `opc` reads the value without echoing it and sends it straight to your organization's secret store over HTTPS, not through the session. The session gets it as an environment variable from its next command, and the agent sees only its name.

You choose who it is for:

| Scope | Available to |
| --- | --- |
| `session` | This session only. The default. |
| `me` | Every session you own, now and later |
| `workspace` | Every session in the organization. Admins only. |

In a session someone else owns, `all my sessions` is not offered: the agent acts as the owner and uses the owner's secrets, not yours.

```
    value: ••••••••••••••••
    for: ❯ this session   all my sessions   everyone (admin)
  ✓ STRIPE_API_KEY set for this session
```

`w` opens the same form on the dashboard, for when you would rather not paste into a terminal. To set a secret before the agent asks, use [`opc secret set`](/reference/commands#opc-secret).

<Warning>
`opc` reads secrets only from a hidden prompt or from standard input. It never takes a secret value as a command-line argument, which other processes on your machine can see.
</Warning>

## Answered somewhere else

The first answer wins. If someone answers in Slack, on the dashboard or in another terminal first, `opc` replaces the ask with what happened:

```
  ✓ allowed by Mo in Slack · terraform apply -auto-approve
```

If you answer at the same moment and lose, your answer is discarded and `opc` shows the one that won. Nothing is applied twice.

## When the turn stops

Interrupting the turn with `Esc` closes its open asks, marked `interrupted`. An ask stays open while the session is suspended: answering it resumes the session.

## In scripts

`opc -p` and `opc wait` cannot answer asks. They exit with code `5` and print the ask, so a person can answer it with `opc a <id>`. See [Scripting](/cli/scripting#when-the-agent-needs-a-person).
