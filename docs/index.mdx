`opc` is a terminal client for [Computer](https://opencomputer.dev/computer), the agent that works for your organization on its own cloud machine. You type, the agent works on the computer, and its output streams into your terminal as the model writes it.

```
$ opc
▸ new session · opus 5.5 · high · ready in 96 ms
> fix the flaky test in segment.test.ts and open a PR
```

Everything the agent does happens on the computer: a large VM with your organization's repositories checked out, its tools installed and a warm model cache. Your laptop sends text and draws glyphs. Nothing on it is read unless you push it.

## What makes it fast

`opc` is a single static binary. It shows a prompt line before the network answers, and you can start typing at once.

- **One round trip to start.** Creating the session and opening the connection happen in parallel. The computer claims a pre-started agent while you type.
- **No batching.** Every fragment of text is forwarded the moment the model emits it, and drawn on the next frame.
- **Nothing on the laptop to wait for.** No runtime to boot, no framework between a token and your terminal.

Run any command with `--timing` to see where the milliseconds went. See [Timing](/reference/timing).

## Slack and opc are two views of one session

A session started in Slack can be attached from a terminal, and a session started in a terminal shows up on the dashboard. Both are clients of the same session. What one person types in Slack appears in the terminal, and the other way round.

```bash
opc a https://acme.slack.com/archives/C07ABC/p1761400000000100
```

## What opc is not

- **Not a local agent.** The agent never runs on your laptop and never reads your files. Use [`opc push`](/cli/files) to send a directory to the computer.
- **Not a sync tool.** Files move only when you run `opc push` or `opc pull`.
- **Not a replacement for the dashboard.** Settings, secrets, members and billing stay on [app.opencomputer.dev](https://app.opencomputer.dev).
