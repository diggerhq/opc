## Shape

Over HTTP, an error is a status and a body:

```json
{ "error": { "code": "ask_closed", "message": "This ask was already answered.", "requestId": "req_8k2m4q7x1v9c", "retryable": false, "ask": { "…": "…" } } }
```

Over the WebSocket, the same object is the `data` of a JSON-RPC error, with `status` added. See [Methods](/api/websocket/methods#errors).

- **`code`** is stable and snake_case. Branch on it.
- **`message`** is one sentence for people. It can change. Do not parse it.
- **`requestId`** is the request, for support. Every HTTP response carries it as the `x-request-id` header too.
- **`retryable`** is `true` when the same request, sent again later with the same idempotency key, can succeed. See [What to retry](#what-to-retry).
- Some codes add fields, listed below. Unknown fields may appear.
- **`field`** names the request field at fault as a dotted path, with indexes in brackets, such as `settings.model` or `answers[0].choices`.

## Codes

| Status | Code | Extra fields | Means |
| --- | --- | --- | --- |
| `400` | `invalid_request` | `field` | A parameter is missing, has the wrong type or is out of range, or the request has a field the route does not know |
| `400` | `unsupported_model` | `field` | The model is not in the session's [capabilities](/api/reference/objects#capabilities) `models` |
| `400` | `unsupported_effort` | `field` | The model does not accept that effort |
| `400` | `unsupported_mode` | `field` | The permission mode is not in `capabilities.modes`, such as one your organization does not allow |
| `400` | `invalid_answer` | `field` | An answer does not fit its ask |
| `400` | `answer_with_secret` | | A secret request is answered by [setting the secret](/api/http/secrets) |
| `400` | `invalid_path` | | A workspace path is absolute, contains `..`, or is not a valid upload name |
| `400` | `invalid_archive` | `entry` | An upload is not a tar archive, or has a refused entry |
| `400` | `invalid_cursor` | | The cursor is unreadable, or was made with other filters |
| `401` | `unauthenticated` | | No key, an unknown key, an expired key or a revoked one |
| `402` | `insufficient_credits` | | Your organization is out of credits |
| `403` | `forbidden` | `reason` | The credential may not do this. `reason` says why: `project_key` for a project-scoped key; `missing_scope`, with `scope`, for a key without that [scope](/api/authentication#scopes); `read_only` for a session attached read-only, or a connection opened with a read-only ticket; `terminal_owner_only` when someone other than the session's owner or an admin opens a [terminal](/api/websocket/terminals). |
| `403` | `admin_required` | | Only admins can do this |
| `404` | `not_found` | | No such route |
| `404` | `session_not_found` | | No such session, or you cannot see it |
| `404` | `turn_not_found`, `ask_not_found`, `path_not_found`, `secret_not_found` | | |
| `409` | `id_conflict` | | The session `id` chosen on create is taken by another session |
| `409` | `idempotency_conflict` | | The key was used for a different request |
| `409` | `ask_closed` | `ask` | The ask already closed. `ask` shows how and by whom. |
| `409` | `session_busy` | | A turn is running, and the action needs none |
| `409` | `turn_not_cancellable` | | Only a `queued` turn can be cancelled |
| `409` | `queue_full` | `retryAfterMs` | 20 turns are already queued |
| `409` | `cursor_ahead` | `session` | `after` is greater than the session's `lastSeq`. `session` is the session now. |
| `409` | `path_exists` | | An upload's name exists and was not uploaded |
| `409` | `feature_unavailable` | `feature` | The session's `capabilities.features` lacks it |
| `409` | `computer_not_set_up` | | Finish setting up your computer on the dashboard |
| `413` | `too_large` | `bytes`, `files` | Over a [limit](/api/reference/limits) |
| `426` | `upgrade_required` | `minVersion` | This build of `opc` is no longer supported. See [Versioning](/api/reference/versioning#opc). |
| `429` | `rate_limited` | `retryAfterMs` | Too many requests. HTTP also sends `Retry-After`. |
| `500` | `internal` | | Our fault. Retry with the same idempotency key. |
| `503` | `computer_unavailable` | `retryAfterMs` | Your computer is starting or being updated. Retry. |
| `503` | `unavailable` | `retryAfterMs` | A temporary failure, or a read with `minSeq` that the server's copy of the log did not reach within 2 seconds. Retry. |

### WebSocket only

These codes come only from WebSocket methods that no HTTP route has:

| Status | Code | Means |
| --- | --- | --- |
| `404` | `terminal_not_found` | The `terminalId` is not open on this connection |
| `409` | `too_far_behind` | `sessions.attach` with an `after` more than 10,000 events back. Read them over [HTTP](/api/http/events) first. |
| `409` | `too_many_attached` | This connection already has 20 sessions attached |
| `409` | `too_many_terminals` | 8 terminals are already open in this session |

Invalid params are JSON-RPC `-32602`, whose `data` is always `{ "code": "invalid_request", "status": 400, "field": "…" }`.

## What to retry

Branch on `retryable`:

| | `retryable` | Do |
| --- | --- | --- |
| `429`, `500`, `503`, `409 queue_full` | `true` | Retry after `retryAfterMs`, or with backoff, with the same idempotency key |
| A timeout, a dropped connection | | Retry the same way |
| `409 idempotency_conflict` | `false` | You reused a key by mistake. Use a new key. |
| Any other `4xx` | `false` | The request will fail the same way |

## Turn failures

A turn that fails has an error in its `turn.failed` event's `error`, in the turn's `error` and in the session's `lastTurn.error`: `{ code, message }` and at most one more field. The session stays usable after any of them.

| `code` | Means | Field |
| --- | --- | --- |
| `model_rejected` | The model provider refused the request: credentials, quota or content policy | |
| `model_unavailable` | The model is no longer available to your organization | `model` |
| `model_stream_failed` | The model call broke off, and its retry failed too | `model` |
| `context_too_long` | The conversation does not fit the model's context, even after compacting | |
| `runtime_lost` | The agent process stopped responding, or the computer running it was lost, and the turn was abandoned | |
| `runtime_failed` | The agent process failed before the turn finished | |
| `tool_failed` | A tool failed in a way the agent could not recover from | `toolName` |
| `agent_failed` | Any other failure | |

These codes are those of OpenComputer's serverless agents, so one client can read both. An interrupted turn does not fail: it ends as `cancelled`.

<Note>
A rate limit from the model provider is not a failure. The call is retried, and each wait is a `model.rate_limited` event. The turn fails with `model_rejected` only when retrying gives up.
</Note>
