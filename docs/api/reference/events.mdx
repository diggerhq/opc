## Shape

A recorded event:

```json
{
  "id": "ev_3k8m2q7x9c1v4b6n",
  "seq": 1184,
  "timestamp": "2026-10-26T09:14:51.007Z",
  "sessionId": "cs_7f3a9k2m4q8r1t6v",
  "turnId": "tn_4m8q2x7c1v9b",
  "type": "tool.started",
  "actor": null,
  "data": { "tool": "Bash", "callId": "toolu_01AbC", "title": "npm test -- segment", "input": { "command": "npm test -- segment" } }
}
```

| Field | Meaning |
| --- | --- |
| `id` | Unique, `ev_` and 16 characters |
| `seq` | Position in the session's log: 1, 2, 3, with no gaps. The cursor for [reading](/api/http/events) and [attaching](/api/websocket/methods#attach). |
| `timestamp` | When it was recorded, by the computer's clock |
| `sessionId` | The session |
| `turnId` | The turn it belongs to, or `null` for session-level events |
| `type` | One of the types below |
| `actor` | The [person](/api/reference/objects#actor) who caused it, or `null` when the agent or the computer did |
| `data` | Fields for the type |

A **delta** is streamed, not recorded. It has no `id`, `seq` or `timestamp`:

```json
{ "type": "message.delta", "sessionId": "cs_7f3a9k2m4q8r1t6v", "turnId": "tn_4m8q2x7c1v9b", "data": { "blockId": "b7", "text": "The flake comes from" } }
```

Deltas reach WebSocket clients that attached with `deltas: true`, and nowhere else. See [the model](/api/model#deltas-are-not-in-the-log).

**Reading rules.** Treat an unknown `type` as informational and keep going. Treat unknown `data` fields the same. Every field listed below is present on every event of its type, `null` when it does not apply.

## Session

| Type | When | `data` |
| --- | --- | --- |
| `session.created` | Always the first event | `title`, `origin`, `settings` |
| `session.status_changed` | The [status](/api/model#sessions) changed | `from`, `to` |
| `session.updated` | Someone changed the title or settings, or allowing a plan changed the mode | `changes`: `{ field: { from, to } }` for each changed field |
| `session.context` | After each model call | `usedTokens`, `windowTokens` |
| `session.compacted` | The conversation was summarized | `beforeTokens`, `afterTokens`, `auto`: `true` when the agent compacted on its own |

## Messages and turns

| Type | When | `data` |
| --- | --- | --- |
| `message.received` | A message was accepted. Recorded before anything runs. | `input`, `mode`, `delivery` |
| `message.held` | The message waits for open asks to close | `askIds` |
| `message.delivered` | A held message reached the agent | `as`: `steering` |
| `turn.queued` | A new turn waits behind others | `position`: 1 for next |
| `turn.steered` | The message joined the running turn | `activeTurnId` |
| `turn.interrupted` | This message interrupted running and queued turns | `interruptedTurnIds` |
| `turn.started` | The agent began the turn | `model`, `effort`, `mode` |
| `turn.completed` | The turn finished | `text`: the agent's last message, `durationMs` |
| `turn.failed` | The turn stopped with an error | `code`, `message`, and `model` or `tool` when named. See [Turn failures](/api/reference/errors#turn-failures). |
| `turn.cancelled` | The turn was interrupted, or was queued when an interrupt came | `reason`: `interrupted`; `input`: the message, so a client can offer it again |

`message.received` is in the turn it started or joined: for `steered` and `held` messages, the running turn's `turnId`.

## Text

| Type | Recorded | When | `data` |
| --- | --- | --- | --- |
| `message.delta` | No | The agent wrote more of a message | `blockId`, `parentCallId`, `text`: the new fragment |
| `message.completed` | Yes | A message is complete | `blockId`, `parentCallId`, `text`: all of it |
| `reasoning.delta` | No | The model reasoned further | `blockId`, `parentCallId`, `text` |
| `reasoning.completed` | Yes | A reasoning block is complete | `blockId`, `parentCallId`, `text`, `redacted`: `true` when the model returned no readable reasoning, `durationMs` |

A turn writes several blocks: text, then tool calls, then more text. `blockId` ties a block's deltas to its completed event. It is unique within the turn. Concatenate the deltas of one `blockId` in arrival order. When the completed event arrives, replace them with its `text`.

## Tools

| Type | Recorded | When | `data` |
| --- | --- | --- | --- |
| `tool.started` | Yes | The agent called a tool | `tool`, `callId`, `parentCallId`, `title`, `input` |
| `tool.delta` | No | A running tool produced output, such as a command's terminal output | `callId`, `text` |
| `tool.completed` | Yes | The tool returned | `tool`, `callId`, `title`, `output`, `changes`, `durationMs` |
| `tool.failed` | Yes | The tool returned an error, or its turn ended before it did | `tool`, `callId`, `title`, `message`, `settledBy` |

- `tool` is the tool's name, such as `Bash`, `Edit`, `Read` or `mcp__linear__create_issue`. `title` is one line for display, such as the command or the file.
- `parentCallId` is `null`, or the `callId` of the subagent call this call was made inside. Text and reasoning events carry it too, so a client can nest a subagent's work under its call.
- `changes` lists the files the call changed, as `[{ "path": "src/a.ts", "status": "modified", "added": 12, "removed": 3 }]`, with `status` one of `added`, `modified` or `deleted`. It is the same for every harness and tool that edits files, and `null` for a call that changed none. Changes a command made, such as `Bash` running a formatter, are not tracked.
- `input` and `output` are JSON values, never JSON text. Each is cut at 64 KiB, with `truncated: true` beside it when it was.
- Every `tool.started` is followed by exactly one `tool.completed` or `tool.failed` with its `callId`, before the turn's last event. When a turn ends with a call still open, `tool.failed` is recorded with `settledBy` naming the turn's ending event, such as `turn.cancelled`. Otherwise `settledBy` is `null`.

## Asks

| Type | When | `data` |
| --- | --- | --- |
| `ask.opened` | The agent raised an ask | `ask`: the [Ask](/api/reference/objects#ask) |
| `ask.closed` | It was answered, dismissed or interrupted | `askId`, `status`, `answer`. The `actor` is who answered or dismissed it. |

A secret ask's `answer` names the scope the secret was set for, never its value.

## Model

| Type | When | `data` |
| --- | --- | --- |
| `usage.recorded` | A model call finished | `model`, `inputTokens`, `outputTokens`, `reasoningTokens`, `cachedTokens`, `cacheWriteTokens`, `costUsd`, `firstTokenMs`, `durationMs` |
| `model.rate_limited` | The model provider asked to wait. The call is retried. | `model`, `retryInMs`, `attempt` |

`firstTokenMs` is from the computer sending the request to the model's first token, as the computer measured it. `opc --timing` shows it as `of which model`.

## Runtime

| Type | When | `data` |
| --- | --- | --- |
| `runtime.starting` | Something has to start before the agent can work | `phase`: `computer` when the computer was asleep, `agent` when only the agent process starts |
| `runtime.connected` | The agent process is ready | `warm`: `true` when a pre-started process was used, `resumed`: `true` when the session was resumed, `ms`: from start to ready |
| `runtime.suspended` | The agent process stopped | `reason`: `idle` or `requested` |
| `runtime.resumed` | The suspended session is ready again | `ms` |

## Files and shells

| Type | When | `data` |
| --- | --- | --- |
| `files.pushed` | Someone uploaded files into the workspace | `path`, `files`, `bytes`, `replaced` |
| `shell.opened` | Someone opened a [shell](/api/websocket/pty) | `ptyId`, `command`: `null` for an interactive shell |
| `shell.closed` | It ended | `ptyId`, `exitCode` |

What is typed in a shell and what it prints are not recorded.

## Order within a turn

For one turn, recorded events come in this order:

1. `message.received`, then `turn.queued` or `turn.started`
2. Blocks and tool calls, in the order the agent produced them, with `ask.*`, `turn.steered`, `usage.recorded` and `session.context` among them
3. `tool.failed` with `settledBy` for any call still open
4. Exactly one of `turn.completed`, `turn.failed` or `turn.cancelled`, last

Nothing is recorded in a turn after its ending event. Events of different turns do not interleave, except `message.received` and `turn.queued` for messages queued while another turn runs.
