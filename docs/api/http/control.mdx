title: "Control"
description: "Interrupt, compact, suspend and resume a session."
---

These routes act on the session as a whole. None waits for the agent: each returns as soon as the request is recorded, with the session as it is at that moment, and the events say when the action is complete. Each is safe to repeat: doing it again when there is nothing to do returns the same response and changes nothing.

## Interrupt

```http
POST /sessions/{id}/interrupt
```

Stops the running turn and cancels every queued turn. What `Esc` does in `opc`.

Returns `202 { "session": Session }` at once. In it, the running turn is `cancelling` and the queued turns are already `cancelled`. Then:

- Each queued turn gets a `turn.cancelled` event with reason `interrupted`, in order, before the response is sent.
- The running turn is told to stop. A tool that was running is stopped; files it had already changed stay changed. Open asks close as `interrupted`. When the agent has stopped, usually within a second, its `turn.cancelled` is recorded, with reason `interrupted` and `forced: false`.
- If the agent has not stopped after 10 seconds, its process is restarted and the turn is cancelled anyway, with `forced: true`.

With nothing running, it returns `200 { "session": Session }` and does nothing. The cancelled turns' inputs are in their `turn.cancelled` events, so a client can offer them again, as `opc` does by putting them back in the prompt.

To wait for the stop without a WebSocket, poll [the turn](/api/http/turns#get-a-turn) until its status is `cancelled`.

To interrupt and send a new message in one request, [send it](/api/http/turns#send-a-message) with `mode: "interrupt"`.

## Compact

```http
POST /sessions/{id}/compact
```

Replaces the conversation so far with a summary, freeing context. The agent keeps working from the summary. `opc` runs it with `/compact`, and the agent compacts on its own when the context is nearly full.

| Field | Meaning |
| --- | --- |
| `instructions` | Optional. What the summary must keep, such as `keep the list of failing tests` |

Compacting runs as its own turn: queued behind a running one, or started at once when idle. The response is a [send receipt](/api/http/turns#send-a-message), `202 { "turnId", "status", "delivery", "duplicate" }`, not the session: it is the one route here that creates a turn. The turn's events include `session.compacted` with the context before and after.

`409 feature_unavailable` when `capabilities.features.compact` is `false`.

## Suspend

```http
POST /sessions/{id}/suspend
```

Stops the agent process now, rather than after two hours idle. The conversation, the workspace and open asks are kept. The next message resumes the session.

Returns `202 { "session": Session }` with the session still `idle` or `waiting`; `runtime.suspended` follows within a few seconds, and the session is then `suspended`.

`409 session_busy` while a turn is running. Interrupt it first, or wait.

An open [shell](/api/websocket/pty) is closed.

## Resume

```http
POST /sessions/{id}/resume
```

Starts the agent process of a suspended session, without sending anything. Sending a message resumes the session anyway, so this is only to save the wait: `opc` calls it when you attach to a suspended session, so the agent is ready by the time you finish typing.

Returns `202 { "session": Session }` as soon as the resume has started, with `status: "starting"`. `runtime.resumed` follows when it is ready. On a session that is not suspended, it returns `200` and does nothing.
