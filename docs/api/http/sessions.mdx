## Create a session

```http
POST /sessions
```

```bash
curl -s "$API/sessions" -H "x-api-key: $OPENCOMPUTER_API_KEY" \
  -H "content-type: application/json" -H "idempotency-key: 6f1c2b7e-…" \
  -d '{ "input": "fix the flaky test in segment.test.ts", "mode": "acceptEdits" }'
```

| Field | Type | Meaning |
| --- | --- | --- |
| `input` | string, optional | The first message. Sent as a turn as soon as the session exists, in the same request. Up to 100,000 characters. |
| `title` | string, optional | Up to 200 characters. Default: taken from `input`, or `Untitled` until the first message. |
| `model` | string, optional | A model `id` from [`capabilities.models`](/api/reference/objects#capabilities). Default: your organization's. |
| `effort` | string, optional | One of the model's `efforts` |
| `mode` | string, optional | A permission mode from `capabilities.modes` |

The response is `201`:

```json
{
  "session": { "id": "cs_7f3a9k2m4q8r1t6v", "status": "starting", "…": "…" },
  "turn": { "id": "tn_4m8q2x7c1v9b", "status": "queued", "input": "fix the flaky test in segment.test.ts", "…": "…" },
  "delivery": "started",
  "duplicate": false
}
```

`turn` and `delivery` are what [sending](/api/http/turns#send-a-message) `input` returned, or `null` without it. The response returns as soon as the session exists. It does not wait for the agent to start: watch `status`, or the `runtime.connected` event.

With an `Idempotency-Key` that already created a session, the response is `200` with the same session, as it is now, and `duplicate: true`. See [Idempotency](/api/reference/idempotency).

<Tip>
To give the agent files before its first message, create the session without `input`, [upload](/api/http/workspace#upload) the files, then [send](/api/http/turns#send-a-message) the message. `opc -p --push` does this. Uploading does not wait for the agent to start, so the three requests take little more than one.
</Tip>

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | A field has the wrong type or is too long. `error.field` names it. |
| `400` | `unknown_model` | `model` is not in `capabilities.models` |
| `400` | `unsupported_effort` | The model does not accept `effort` |
| `403` | `mode_not_allowed` | Your organization does not allow `mode` |
| `402` | `insufficient_credits` | Your organization is out of credits |
| `409` | `idempotency_conflict` | The key was used with a different body |
| `409` | `computer_not_set_up` | Your organization has not finished setting up its computer |

## List sessions

```http
GET /sessions
```

```bash
curl -s "$API/sessions?owner=me&limit=20" -H "x-api-key: $OPENCOMPUTER_API_KEY"
```

| Query | Meaning |
| --- | --- |
| `owner` | `me` (default) for sessions you own, `anyone` for every session you can see, or a person's `usr_` id |
| `status` | One status, or several separated by commas, such as `running,waiting` |
| `origin` | `slack` or `api` |
| `q` | Matches titles, case-insensitively |
| `order` | `active` (default): most recently active first. `created`: newest first. |
| `limit` | 1 to 100. Default 50. |
| `cursor` | The `nextCursor` from the previous page |

```json
{
  "sessions": [{ "id": "cs_7f3a9k2m4q8r1t6v", "title": "flaky test in segment.test.ts", "status": "waiting", "…": "…" }],
  "nextCursor": "eyJ0IjoiMjAyNi0xMC0yNlQwOToxNDo1MS4wMDdaIiwiaSI6ImNzXzdmM2EifQ"
}
```

Each session is the full [object](/api/reference/objects#session) without `capabilities` and `queued`, which only `GET /sessions/{id}` returns. `nextCursor` is `null` on the last page. A cursor is opaque, and is valid only with the same filters and `order`.

**Order and paging.** With `order=active`, a session that becomes active while you page moves to the top, so a later page can skip or repeat it. That is right for a screen like `opc ls`, which reads the first page again to refresh. To walk every session exactly once, use `order=created`.

**Visibility.** You see every session in your organization except those started in a Slack channel you are not a member of. A Slack session's channel membership is checked when the list is read.

## Get a session

```http
GET /sessions/{id}
```

Returns `{ "session": … }`, the complete [object](/api/reference/objects#session), current to its `lastSeq`.

`404 session_not_found` when the session does not exist or you cannot see it. The two cases are not distinguished.

## Update a session

```http
PATCH /sessions/{id}
```

```bash
curl -s -X PATCH "$API/sessions/cs_7f3a9k2m4q8r1t6v" -H "x-api-key: $OPENCOMPUTER_API_KEY" \
  -H "content-type: application/json" -d '{ "model": "claude-sonnet-5-5", "effort": "medium" }'
```

| Field | Applies |
| --- | --- |
| `title` | At once. 1 to 200 characters. |
| `model` | From the next turn. Must be in `capabilities.models`. |
| `effort` | From the next turn. Must be one of the model's `efforts`, which is checked against the new `model` when both are sent. |
| `mode` | At once, to the running turn too. Must be in `capabilities.modes`. |

Fields you leave out are not changed. The response is `{ "session": … }` after the change, and a `session.updated` event records who changed what.

Changing `model` resets `effort` to the new model's default when the current effort is not one of its `efforts`. The response shows the result.

Any member who can see the session can update it. Errors are those of [create](#create-a-session), and `400 invalid_request` for an empty body.
