---
title: "Workspace"
description: "List, download and upload files in a session's workspace."
---

Each session has its own workspace on the computer, with every connected repository checked out. These routes are how files move between it and anywhere else. They are what `opc push` and `opc pull` use. See [Files](/cli/files) for the rules from a person's side.

They work on suspended sessions without resuming them, and never wait for the agent.

## List files

```http
GET /sessions/{id}/workspace/files
```

| Query | Meaning |
| --- | --- |
| `path` | A directory relative to the workspace. Default: the workspace itself. |
| `depth` | How many levels to list, 1 to 10. Default 1. |

```json
{
  "path": "",
  "entries": [
    { "path": "billing", "type": "dir", "size": null, "modifiedAt": "2026-10-26T09:02:40.118Z", "pushed": { "by": { "id": "usr_2k9d8f7a", "name": "Igor Zalutski", "via": "opc" }, "at": "2026-10-26T09:02:40.118Z" } },
    { "path": "billing-service", "type": "dir", "size": null, "modifiedAt": "2026-10-26T08:58:01.004Z", "pushed": null }
  ],
  "truncated": false
}
```

| Field | Meaning |
| --- | --- |
| `type` | `file`, `dir` or `symlink` |
| `size` | Bytes, for files |
| `pushed` | For directories at the top of the workspace: who uploaded it and when, or `null` when it was not uploaded |
| `truncated` | `true` when the listing stopped at 10,000 entries |

`.git` directories are listed but never descended into.

## Download

```http
GET /sessions/{id}/workspace/archive?path={path}
```

Returns the directory or file at `path` as a tar archive, `Content-Type: application/x-tar`, streamed as it is read. Send `Accept-Encoding: gzip` to have it compressed. Paths in the archive are relative to `path`. A file comes as an archive of one entry.

- `.git` directories are left out. Nothing else is.
- Symbolic links are archived as links.
- Ownership is not kept. Modes are kept for the executable bit only.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_path` | `path` is absolute or contains `..` |
| `404` | `path_not_found` | |
| `413` | `too_large` | Over 1 GiB or 100,000 files. `error.bytes` and `error.files` say how much. |

## Upload

```http
PUT /sessions/{id}/workspace/archive?path={name}
```

```bash
tar -C ~/src/billing --exclude .git -cz . | curl -s -X PUT \
  "$API/sessions/cs_7f3a9k2m4q8r1t6v/workspace/archive?path=billing" \
  -H "x-api-key: $OPENCOMPUTER_API_KEY" -H "content-type: application/x-tar" -H "content-encoding: gzip" \
  --data-binary @-
```

Writes the archive's contents to `workspace/{name}`, replacing what was there.

| Rule | Why |
| --- | --- |
| `name` is one level: letters, digits, `.`, `-` and `_`, not starting with `.` | Uploads sit beside the repositories, never inside them |
| A `name` that exists and was not uploaded is refused with `409 path_exists` | An upload can never overwrite a repository or the agent's work |
| A `name` uploaded before is replaced entirely, and the response says so | Re-pushing is how you update it |
| Entries with absolute paths, `..`, hard links or device files are refused with `400 invalid_archive` | |

The server applies no ignore rules: it writes what it receives. `opc push` applies `.gitignore` and `.opcignore` before sending.

The response is `200`:

```json
{ "path": "billing", "files": 412, "bytes": 3245112, "replaced": null }
```

`replaced` is `{ by, at }` for the upload it replaced, or `null`. A `files.pushed` event is recorded, and the agent's next turn begins with a note naming the directory and who pushed it.

The upload is written to a temporary directory and moved into place when complete, so the agent never sees half an upload. An upload that fails changes nothing.

Send an `Idempotency-Key` to make retries safe. A repeat with the same key returns the first response without writing again.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_path` | `name` breaks the rules above |
| `400` | `invalid_archive` | The body is not a tar archive, or has a refused entry. `error.entry` names it. |
| `409` | `path_exists` | `name` exists and was not uploaded |
| `413` | `too_large` | Over 1 GiB or 100,000 files, unpacked |
