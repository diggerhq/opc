---
title: "Secrets"
description: "Give sessions credentials without putting them in the conversation."
---

A secret is a named value, such as `STRIPE_API_KEY`, that sessions get as an environment variable. The agent sees its name, never its value. Values are stored encrypted, are never returned by the API, and never pass through a session's events or connection.

This is how a [secret request](/api/reference/objects#secret-request) is answered, and how to give sessions credentials before they ask. Each secret is a [Secret](/api/reference/objects#secret) object: its name and where it applies, never its value.

## Scopes

The scope is in the route: a secret is set on a session, on you, or on the organization.

| Scope | Route | Reaches | Who can set it |
| --- | --- | --- | --- |
| `session` | `/sessions/{id}/secrets/{name}` | One session | Any member who can see the session |
| `me` | `/me/secrets/{name}` | Every session you own, now and later | You, for yourself |
| `organization` | `/organization/secrets/{name}` | Every session in the organization | Admins |

When the same name is set in several scopes, a session uses the narrowest: `session`, then its owner's `me`, then `organization`.

`me` means the session's owner. A `me` secret you set reaches only sessions you own. So in someone else's session, set a secret on the session, or on the organization if you are an admin.

## Set a secret

```http
PUT /sessions/{id}/secrets/{name}
PUT /me/secrets/{name}
PUT /organization/secrets/{name}
```

```bash
read -rs value && jq -n --arg v "$value" '{ value: $v }' \
  | curl -s -X PUT "$API/sessions/cs_7f3a9k2m4q8r1t6v/secrets/STRIPE_API_KEY" -H "x-api-key: $OPENCOMPUTER_API_KEY" \
      -H "content-type: application/json" --data-binary @-
```

| Field | Meaning |
| --- | --- |
| `value` | The value, up to 64 KiB. Required, not empty. |
| `file` | Optional. `true` delivers the value as a file whose path is in the variable, for credentials that tools read from a file. Default `false`. A secret request's `secret.file` says what the agent asked for. |

`name` is 1 to 128 characters: capital letters, digits and `_`, not starting with a digit. Setting an existing name in the same scope replaces its value.

```json
{
  "secret": { "name": "STRIPE_API_KEY", "scope": "session", "sessionId": "cs_7f3a9k2m4q8r1t6v", "file": false, "setBy": { "id": "usr_2k9d8f7a", "name": "Igor Zalutski", "via": "api", "client": null }, "updatedAt": "2026-10-26T09:07:30.551Z" },
  "answeredAsks": ["ak_9b4m8q2x7c1v"]
}
```

`answeredAsks` lists the open secret requests with this name that the secret reaches, which are now answered.

A session gets a new or changed value from its next command. Processes already running keep the environment they started with.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | A bad name, or an empty or oversized value |
| `403` | `admin_required` | `organization` scope, and you are not an admin |
| `403` | `forbidden` | The key lacks the `secrets:write` scope: `reason` is `missing_scope` |
| `404` | `session_not_found` | |

## List secrets

```http
GET /secrets
```

| Query | Meaning |
| --- | --- |
| `sessionId` | Only secrets that reach this session, with the one in effect marked |
| `scope` | Only this scope: `session`, `me` or `organization` |
| `limit` | 1 to 100. Default 20. |
| `cursor` | The `nextCursor` from the previous page |

Returns `{ "secrets": [Secret…], "nextCursor" }`, by name: names and metadata, never values. You see `organization` secrets, your own `me` secrets, and `session` secrets of sessions you can see. With `sessionId`, each has `"effective": true` or `false`; without it, `effective` is `null`.

## Delete a secret

```http
DELETE /sessions/{id}/secrets/{name}
DELETE /me/secrets/{name}
DELETE /organization/secrets/{name}
```

Returns `204`. Deleting a secret does not change the environment of processes already running. Who can delete is who can set.

| Status | Code | When |
| --- | --- | --- |
| `403` | `admin_required` | `organization` scope, and you are not an admin |
| `404` | `secret_not_found` | No secret with this name in this scope |
| `404` | `session_not_found` | |

<Warning>
Do not put secret values in messages. A message is recorded in the session's events, shown in Slack and on the dashboard, and sent to the model. The agent is instructed to ask for a secret rather than accept one in a message.
</Warning>
