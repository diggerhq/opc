---
title: "Secrets"
description: "Give sessions credentials without putting them in the conversation."
---

A secret is a named value, such as `STRIPE_API_KEY`, that sessions get as an environment variable. The agent sees its name, never its value. Values are stored encrypted, are never returned by the API, and never pass through a session's events or connection.

This is how a [secret ask](/api/reference/objects#secret) is answered, and how to give sessions credentials before they ask.

## Scopes

| Scope | Reaches | Who can set it |
| --- | --- | --- |
| `session` | One session | Any member who can see the session |
| `me` | Every session you own, now and later | You, for yourself |
| `workspace` | Every session in the organization | Admins |

When the same name is set in several scopes, a session uses the narrowest: `session`, then its owner's `me`, then `workspace`.

`me` means the session's owner. A `me` secret you set reaches only sessions you own. So in someone else's session, set a secret for the `session` scope, or for `workspace` if you are an admin.

## Set a secret

```http
PUT /secrets/{name}
```

```bash
read -rs value && jq -n --arg v "$value" '{ value: $v, scope: "session", sessionId: "cs_7f3a9k2m4q8r1t6v" }' \
  | curl -s -X PUT "$API/secrets/STRIPE_API_KEY" -H "x-api-key: $OPENCOMPUTER_API_KEY" \
      -H "content-type: application/json" --data-binary @-
```

| Field | Meaning |
| --- | --- |
| `value` | The value, up to 64 KiB. Required, not empty. |
| `scope` | `session`, `me` or `workspace` |
| `sessionId` | Required with `session`, refused with the others |
| `file` | Optional. `true` delivers the value as a file whose path is in the variable, for credentials that tools read from a file. Default `false`, or the open ask's `file`. |

`name` is 1 to 128 characters: capital letters, digits and `_`, not starting with a digit. Setting an existing name in the same scope replaces its value.

```json
{
  "secret": { "name": "STRIPE_API_KEY", "scope": "session", "sessionId": "cs_7f3a9k2m4q8r1t6v", "file": false, "setBy": { "id": "usr_2k9d8f7a", "name": "Igor Zalutski", "via": "api" }, "updatedAt": "2026-10-26T09:07:30.551Z" },
  "answeredAsks": ["ak_9b4m8q2x7c1v"]
}
```

`answeredAsks` lists the open secret asks with this name that the secret reaches, which are now answered.

A session gets a new or changed value from its next command. Processes already running keep the environment they started with.

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | A bad name, an empty or oversized value, or `sessionId` with the wrong scope |
| `403` | `admin_required` | `workspace` scope, and you are not an admin |
| `404` | `session_not_found` | |

## List secrets

```http
GET /secrets
```

| Query | Meaning |
| --- | --- |
| `sessionId` | Only secrets that reach this session, with the one in effect marked |

Returns `{ "secrets": [Secret…] }`: names and metadata, never values. You see `workspace` secrets, your own `me` secrets, and `session` secrets of sessions you can see. With `sessionId`, each has `"effective": true` or `false`.

## Delete a secret

```http
DELETE /secrets/{name}?scope={scope}&sessionId={sessionId}
```

Returns `204`. Deleting a secret does not change the environment of processes already running.

<Warning>
Do not put secret values in messages. A message is recorded in the session's events, shown in Slack and on the dashboard, and sent to the model. The agent is instructed to ask for a secret rather than accept one in a message.
</Warning>
